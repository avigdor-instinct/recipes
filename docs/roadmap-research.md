# מחקר best practices לרודמאפ CookFlow (2026-09-18)

עיקרון מוצר: הדפוס החזק אצל Paprika, Samsung Food/Whisk, SideChef ו-MyFitnessPal הוא שרשרת אחת: מתכון מובנה -> התאמת מנות -> רשימת קניות -> בישול מודרך -> תיעוד אופציונלי. להגדיר כבר עכשיו סכמת מתכון אחידה: מזהה, מספר מנות, רכיבים מפורקים לכמות/יחידה/מוצר/הערה, שלבים, זמנים, תגיות וגרסאות. להוסיף Recipe JSON-LD.

## עריכת כמויות ומספר מנות
- Best practice: בורר מנות ליד הכותרת; שינוי מיידי של כל הכמויות; הצגת המנה המקורית + Reset; שברים קריאים; כמויות בתוך השלבים משתנות יחד; ערכים תזונתיים מתעדכנים.
- MVP סטטי: baseQuantity + יחידה + מנות בסיס לכל רכיב; כפתורי 0.5x/1x/2x מחשבים בדפדפן; שמירה ב-localStorage; כמויות בשלבים = placeholders מקושרים ל-ingredient ID.
- להימנע: פריטים לא-ליניאריים בלי הערה ("לפי הטעם", שמן לטיגון, גודל תבנית), עיגול 1/3 ל-0, המרת גרם לכוסות אוטומטית, שינוי ברשימה אך לא בשלבים, דיוק שווא.

## רשימות קניות
- Best practice: הוספה בלחיצה, איחוד מרכיבים זהים בין מתכונים, קיבוץ לפי מחלקה, התאמה למנות, סימון/עריכה/הוספה ידנית. Pantry שלב מאוחר.
- MVP: localStorage, איחוד רק כשמוצר+יחידה זהים, קבוצות בסיסיות, סימון/מחיקה, העתקה ל-WhatsApp, הדפסה, ייצוא JSON.
- להימנע: חיבור נאיבי "בצל"/"2 בצלים", המרות יחידות לא מבוססות, הבטחת סנכרון בין מכשירים בלי backend.

## דיאטות, אלרגנים והעדפות
- Best practice: להפריד תגיות עובדתיות מהעדפות; להסביר למה מתכון תויג; סינון רב-בחירה; אלרגנים דורשים אימות.
- MVP: dietTags, allergens, mayContain, תחליפים ופילטרים באינדקס; "מתאים/לא מתאים/דורש בדיקה"; בדיקה אנושית ב-PR.
- להימנע: הסקת "ללא גלוטן" מהשם, הבטחת בטיחות אלרגנית, "דל פחמימה"/"בריא" כעובדות רפואיות. להזכיר אריזות וזיהום צולב.

## קלוריות וערכים תזונתיים
- Best practice: למנה ולכל המתכון, גודל מנה ברור, מקור ותאריך, סימון כאומדן, תיקון התאמת רכיב.
- MVP: שדות ידניים/נבדקים (קלוריות, חלבון, פחמימות, שומן, סיבים, נתרן). בעתיד: חישוב ב-build מול USDA FoodData Central, שמירה בקובץ. לא לחשוף API key ב-Pages.
- להימנע: מספר מדויק ללא מקור, שכחת שמן/רטבים, שינוי מנות בלי עדכון תזונה.

## התאמה ל-Mounjaro / GLP-1
- Best practice: שכבת עזר, לא "דיאטת Mounjaro". מנות קטנות, חלבון וצפיפות תזונתית, שתייה, שמירת מסת שריר, התאמות GI. אין כלל אחיד.
- MVP: מצב "מנה קטנה / חלבון קודם" (1/2 או 2/3 מנה), חלבון למנה, חלוקה לקופסאות קטנות, טיפים עדינים (אפייה במקום טיגון). תגיות: smallPortionFriendly, proteinForward, gentleOption. הבהרה: לא ייעוץ רפואי.
- להימנע: מינון/תזמון תרופה, יעדים אישיים, הבטחת הפחתת תופעות, "בטוח ל-Mounjaro", עידוד אכילה מועטת מדי.

## מעקב משקל
- Best practice: אופציונלי, פרטי, מגמה ולא מספר בודד, הערות, יעד בבחירה, ייצוא ומחיקה מלאה.
- MVP: IndexedDB/localStorage בלבד: תאריך, משקל, הערה, גרף 7/30 יום, ק"ג/ליברות, CSV/JSON, ייבוא ומחיקה. לומר במפורש שהמידע בפרופיל הדפדפן ואינו מוצפן.
- להימנע: analytics על נתוני בריאות, שיתוף כברירת מחדל, רצפים מענישים, התראות אשמה, טענת אבטחה שאין בפועל.

## תכונות סמוכות ששווה לשקול
תכנון שבועי שמייצר רשימה מאוחדת; חיפוש לפי זמן/רכיב/דיאטה/קושי/חלבון; טופס מקומי שמייצר JSON/Markdown או GitHub Issue; מצב בישול נגיש לטאבלט (טקסט גדול, שלב יחיד, timers מרובים, קול, מקלדת); החלפות עם השפעה גלויה על אלרגנים ותזונה; PWA/offline.

## סדר מומלץ
1. סכמת מתכון אחידה + JSON-LD + עריכת מנות.
2. רשימת קניות מקומית + חיפוש/פילטרים.
3. תזונה ידנית עם מקור ואומדן.
4. תכנון שבועי + PWA.
5. מצב GLP-1 זהיר ומבוסס נתונים.
6. משקל רק אחרי מסך פרטיות, ייצוא ומחיקה.
